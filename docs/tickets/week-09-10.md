TC-5 (first half)
**Algorithm:** Algorithm 4, the PFM (Phase A §3.5.4, Appendix B.4): a shared temporal
Transformer over a window of clip vectors, one head per domain, predicting the event type and
the time until it; confidence `κ = 1 − H(p) / log|C_d|`; an alert when `max(p) ≥ θ_d`.
Loss `CE + α · MSE(Δt)`, summed over the domains with weights `λ_d`.
**Ships in:** `notebooks/` · `scripts/` · `services/pfm/` · `services/query/` · `frontend/` ·
`docker-compose.yml`

## OMNI-917 · Measures that fit forecasting; the event-only model trained again by them · Sat 28 – Sun 29 Nov

**Why:** the AUC used so far puts every sample of every window in one pile. Two problems: a sample 30 s before the
event counts as "event" though nothing is visible yet, and samples from different videos are compared, so a model
can win by telling places apart (K-36; also "Auditing Frame-Level AUC", arXiv 2608.11985). OMNI-916 shows the
cost: the event-only model ties v2 on that AUC (0.7315 against 0.7293) but rises twice as much (+0.170 against
+0.076) and warns on more event windows (43 of 114 against 32). These measures ask the forecasting question
directly. The event-only model's epoch was chosen by the pooled AUC, so it is **trained again**, the epoch chosen
by the new measure. **Only the event-only method is trained:** the product asks "is something coming, and when", which
is exactly its question (Ahmad's call, 28 Nov); v2 is not trained again. **[SM-2, SM-3]**

- [x] **Decision first, before any number is computed** (a new D-number), written with the definitions below:
  - **SM-2 revised again:** held-out UCF-Crime **within-window AUC ≥ 0.70** for the model the product serves.
    The pooled AUC stays reported beside it, for comparison with papers
  - **Which model the product serves (v2 or the event-only model):** on UCF-Crime's validation, the one with the
    higher within-window AUC, only if it beats the other by more than the larger seed spread of that measure
    **and** its flat-line check on normal windows is ≤ 0.60. Otherwise v2 stays. Say openly that the rise was
    already seen in OMNI-916
  - The `close` / `far` ranges per domain (below), fixed here
- [x] Code in `scripts/pfm_heldout.py` (or a small `scripts/pfm_measures.py`), each function tested on tiny
      hand-made windows with a known answer:
  1. **Within-window AUC (the main one).** Inside each event window, every `close` sample (UCF-Crime: τ in
     [0, 10) s) against every `far` sample (UCF-Crime: τ ≥ 20 s) of **the same window**: the share where `close`
     scores higher (ties count half). Score = `1 − p(Normal)`. Mean over windows, and the number of windows
     skipped (no `close` or no `far` sample). CCD: `close` and `far` chosen from its short windows (about 3.5 s of
     lead-up), for example the last 1 s against the first 1 s, fixed in the decision
  2. **Flat-line check on normal windows.** The same comparison inside each normal window, its last part against
     its first part (the same lengths as `close` and `far`). About 0.5 is right; well above 0.5 means the score
     climbs with time whatever happens, and measure 1 is not to be trusted
  3. **Per-window AUC.** One score per window, its highest `1 − p(Normal)` before the event; event windows
     against normal windows
  4. **AP and mTTA** (the accident-anticipation standard: DSA, GCRNN, DSTA on CCD). Sweep the warning line from
     high to low; an event window is a hit if it warns before the event, a normal window a false alarm if it warns
     at all; AP is the area under precision-recall, mTTA the mean lead time over the sweep. Also the detection rate
     (event windows warned) at the 10% line we already use
  5. **The pooled AUC as today**, unchanged, so old and new numbers sit side by side
- [x] **Training chooses its epoch by the new measure:** after every epoch, on validation, the within-window AUC on
      UCF-Crime decides `best.pt` (not the pooled AUC); every epoch's five measures go into the history, so a later
      choice never needs a new run. Tested
- [x] **Amend the decision (D-64) before training:** the event-only method is the served model's method; the
      served model is its best seed by the within-window AUC on UCF-Crime's validation, and it must pass the
      flat-line check (≤ 0.60) on normal windows. v2 is no longer a candidate; its old checkpoint is measured once
      on validation, for reference only

      **Colab: the event-only model trained again**, every other setting as OMNI-916 (`minus_first`, `labels="event"`,

- [ ] Validation: every seed, both domains, all five measures in one table, v2's old checkpoint beside it for
      reference. The decision's rule applied in the notebook
- [ ] Held-out **once**, only for the chosen model (this replaces OMNI-916's last held-out item): all five

- [ ] `results.md`: SM-2's row and the OMNI-916 / OMNI-917 rows the same day

  sequence of moments, not a sentence.
- [Saving and loading models](https://pytorch.org/tutorials/beginner/saving_loading_models.html)
  — Colab sessions end; training must resume, and serving loads once.
- [The CCD paper: uncertainty-based accident anticipation](https://arxiv.org/abs/2008.00334) — how CCD's results are
  usually reported.
- [Threshold selection](https://scikit-learn.org/stable/modules/model_evaluation.html) — set
  on validation, never on the test data.
